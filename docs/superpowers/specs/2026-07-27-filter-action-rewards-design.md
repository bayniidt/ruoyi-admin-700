# 奖励明细过滤动作奖励设计

## 目标

“奖励明细”页面不展示 PartnerStack 返回的动作奖励，并且顶部奖励笔数、待发佣金、已发佣金只统计过滤后仍可见的奖励。

## 范围

- 仅修改前端。
- 不修改 PartnerStack 接口、后端数据或数据库。
- 以原始字段 `item.source.type === 'action'` 判断动作奖励，避免依赖中文展示文案。
- 其他来源（包括 `transaction` 和未知来源）保持现有显示与统计逻辑。

## 数据流

1. 调用现有 `getPartnerStackRewards({ limit: 100 })`。
2. 从响应中提取奖励数组。
3. 过滤掉 `source.type` 为 `action` 的记录。
4. 使用同一个过滤后数组生成 `rewardList`。
5. 使用同一个过滤后数组计算 `rewardSummary`。

## 验证

- 混合输入中，动作奖励不会出现在表格数据中。
- 奖励笔数和金额不包含动作奖励。
- 交易返佣及未知奖励来源仍然保留。
- 前端生产构建成功。
